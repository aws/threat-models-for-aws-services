# Amazon Simple Storage Service (s3) Threat Model

[Threat Summary](#threat-summary) · [Threats](#threats) · [Mitigations](#mitigations) · [Implementations](#implementations) · [Appendix](#appendix)

## Overview

Amazon S3 is an object storage service for storing and retrieving any amount of data from anywhere. Data is kept as objects, each made of content and descriptive metadata, inside named containers in a chosen AWS Region.

41 threats and 32 mitigations across 5 resource types and 112 API operations. 20 of 38 mitigation goals are covered, implemented by 124 implementations.

Source service model: [s3](https://github.com/aws/api-models-aws/blob/3d89dd029ebd13b775ab5d22e5075399f20b35e4/models/s3/service/2006-03-01/s3-2006-03-01.json)

## Threats

Each scoping statement below describes the exposure the threat's mapped mitigations address. It assumes those mitigations are not applied and makes no claim about your resources.

### Threat.S3.1

Untrusted IAM principal, operating from a governed VPC network, can use the governed VPC network to make Amazon S3 service API calls.

**Impacts:** [Data Collection](../threat-impacts.md#data-collection), [Data Exfiltration](../threat-impacts.md#data-exfiltration)

**Mitigations:** [Mitigation.S3.2](#mitigations32)

**Frameworks:** MITRE ATT&CK [T1530](https://attack.mitre.org/techniques/T1530/), [T1537](https://attack.mitre.org/techniques/T1537/)

**Scoping** (for [Identity Perimeter - Untrusted principal access from a governed VPC network](../potential-threats.md#identity-perimeter---untrusted-principal-access-from-a-governed-vpc-network)): Amazon S3 is reachable from your VPC through a gateway VPC endpoint or an interface VPC endpoint (powered by AWS PrivateLink). An IAM principal from outside your organization can use that network path to make Amazon S3 API calls with its own credentials. That access enables transfer of data from your VPC to Amazon S3 buckets in an AWS account outside your organization.

**Request parameters**

| Operation | Parameters |
|---|---|
| `s3:GetObject` | `$.Bucket`, `$.Key` |
| `s3:PutObject` | `$.Body`, `$.Bucket`, `$.Key` |

### Threat.S3.2

IAM principal, with IAM permissions on untrusted Amazon S3 resources, can interact with those untrusted resources from a governed VPC network.

**Impacts:** [Data Collection](../threat-impacts.md#data-collection), [Data Exfiltration](../threat-impacts.md#data-exfiltration)

**Mitigations:** [Mitigation.S3.1](#mitigations31)

**Frameworks:** MITRE ATT&CK [T1530](https://attack.mitre.org/techniques/T1530/), [T1537](https://attack.mitre.org/techniques/T1537/)

**Scoping** (for [Resource Perimeter - Access to untrusted resource from a governed VPC network](../potential-threats.md#resource-perimeter---access-to-untrusted-resource-from-a-governed-vpc-network)): Amazon S3 API calls from your VPCs can target buckets in another account. An IAM principal on your network whose credentials hold permissions on such a bucket can copy your data into it or download untrusted content from it.

**Data perimeter:** `GetObject` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Data perimeter:** `GetObjectVersion` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Data perimeter:** `HeadBucket` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Data perimeter:** `ListBucket` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Data perimeter:** `PutObject` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Data perimeter:** `PutObjectAcl` might require access to service-owned buckets, which are buckets that are managed in service accounts.

**Request parameters**

| Operation | Parameters |
|---|---|
| `s3:CopyObject` | `$.Bucket`, `$.x-amz-copy-source` |
| `s3:GetObject` | `$.Bucket`, `$.Key` |
| `s3:PutObject` | `$.Body`, `$.Bucket` |

### Threat.S3.AccessPointObject.1

IAM principal, with IAM permissions to create or modify an Amazon S3 access point object, can encrypt the object data and object versions it writes or updates through the access point with key material outside the AWS account owner's control.

**Impacts:** [Data Encrypted for Impact](../threat-impacts.md#data-encrypted-for-impact), [Inhibit System Recovery](../threat-impacts.md#inhibit-system-recovery)

**Mitigations:** [Mitigation.S3.AccessPointObject.2](#mitigations3accesspointobject2)

**Frameworks:** MITRE ATT&CK [T1486](https://attack.mitre.org/techniques/T1486/), [T1490](https://attack.mitre.org/techniques/T1490/)

**Scoping** (for [Data loss through inaccessible encryption key](../potential-threats.md#data-loss-through-inaccessible-encryption-key)): An IAM principal able to write an access point object or update its encryption chooses the KMS key that encrypts your object data by setting `$.x-amz-server-side-encryption-aws-kms-key-id` and `$.ObjectEncryption.SSEKMS.KMSKeyArn`. If that key material sits outside your control, its holder can later revoke or delete it and leave that object data unreadable.

**Request parameters**

| Operation | Parameters |
|---|---|
| `s3:PutObject` | `$.x-amz-server-side-encryption-aws-kms-key-id`, `$.x-amz-server-side-encryption-customer-key` |
| `s3:UpdateObjectEncryption` | `$.ObjectEncryption.SSEKMS.KMSKeyArn` |

### Threat.S3.AccessPointObject.2

IAM principal, with IAM permissions to create or modify an Amazon S3 access point object, can configure the access point object without required tagging information.

### Resources

#### AccessPointObject

*DATA_STORE*

An access point object is an Amazon S3 object that applications read, write, and manage through a named S3 access point. Requests target the access point instead of the bucket, while the data remains in its underlying data source, such as a general purpose bucket.

- IAM resource ARN: `arn:${Partition}:s3:${Region}:${Account}:accesspoint/${AccessPointName}/object/${ObjectName}`
- 24 operations, 7 threats, 4 mitigations

#### Bucket

*DATA_STORE*

An Amazon S3 bucket is a container that stores objects, such as files and their metadata, in a chosen AWS Region. It is designed to provide durable, scalable storage for data lakes, websites, backups, archives, and application data, with no servers to manage.

- IAM resource ARNs: `arn:${Partition}:s3:::${BucketName}`, `arn:${Partition}:s3express:${Region}:${Account}:bucket/${BucketName}`
- CloudFormation: `AWS::S3::Bucket`, `AWS::S3::BucketPolicy`, `AWS::S3Express::BucketPolicy`, `AWS::S3Express::DirectoryBucket`
- AWS Config: `AWS::S3::Bucket`, `AWS::S3Express::BucketPolicy`, `AWS::S3Express::DirectoryBucket`
- 76 operations, 19 threats, 18 mitigations

#### MultipartUpload

*DATA_STORE*

A multipart upload lets you send a single large object to Amazon S3 as a series of independent parts. Each part is a contiguous portion of the object's data, and parts can be sent in any order or in parallel.

- 7 operations, 4 threats, 2 mitigations

#### Object

*DATA_STORE*

An Amazon S3 object is the fundamental unit of data stored in Amazon S3. Each object pairs its content with a unique key, descriptive metadata, and an optional version identifier. Objects reside within buckets and can hold anything from an empty file to multi-terabyte datasets.

- IAM resource ARN: `arn:${Partition}:s3:::${BucketName}/${ObjectName}`
- 32 operations, 8 threats, 5 mitigations

#### ObjectLambdaAccessPoint

*INTEGRATION*

An Object Lambda access point is an Amazon S3 endpoint that runs your AWS Lambda code on data as it is retrieved. Read, list, and metadata requests sent through the endpoint invoke the attached function, and the transformed result returns to the application. Other requests are handled as standard S3 requests without transformation.

- IAM resource ARN: `arn:${Partition}:s3-object-lambda:${Region}:${Account}:accesspoint/${AccessPointName}`
- 1 operations, 1 threats, 1 mitigations
